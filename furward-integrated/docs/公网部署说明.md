## HTTPS

本服务器已由原 `dzq-proxy.service` 管理有效的 IP 证书，新预览使用同一张 IP 证书文件，但使用独立 Caddy 进程、配置、数据目录和监听端口。部署预览不需要重启或改写原代理。

`furward-preview-certificate.timer` 每小时比较证书摘要。证书续期后，只强制重新加载新的预览代理，使其读入更新后的证书。原证书的签发与自动续期仍由原代理负责。证书私钥不会打包或复制到本地源码。

这些配置针对当前服务器已有的 Caddy 路径及 `dzq-proxy` 用户；搬迁到别的服务器时需要配置自己的域名/证书，不能直接照搬这里的绝对路径。

## 更新与检查

将新源码上传到独立工程目录，保留服务器 `web/.env.production` 和 Docker 数据卷，然后在服务器执行：

```sh
cd /opt/furward-preview
docker compose -f deploy/compose.yml build
docker compose -f deploy/compose.yml up -d
docker compose -f deploy/compose.yml ps
curl --fail https://8.147.109.174:8088/api/demo/health
systemctl status furward-preview-tls.service
systemctl list-timers furward-preview-certificate.timer
```

如改了 Caddy 配置，先用服务器现有 Caddy 二进制 `validate`，通过后再 `systemctl reload furward-preview-tls.service`。不要操作原站的 `dzq-proxy.service`。

在本机项目根目录验证公网会话、WebSocket、隔离和完整路线：

```sh
demo-service/.venv/bin/python scripts/check-live.py https://8.147.109.174:8088 --full-route
```

验收脚本包含两分钟实际速度行走；它创建自己的测试会话，并在结束时清理。源码 ZIP 不包含 CMS 数据库或上传图片，交付时如需要这些内容，应另外使用 `web/scripts/selfhost-backup.mjs` 备份数据目录。

## 停止独立预览

```sh
cd /opt/furward-preview
docker compose -f deploy/compose.yml stop
systemctl stop furward-preview-tls.service
```

以上命令保留内容数据，不影响原站。再次运行 Compose `up -d` 和 `systemctl start furward-preview-tls.service` 即可恢复。
