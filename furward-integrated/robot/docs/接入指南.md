# 接入指南：需要手动接入的外部服务

> 适用代码：`ver2/`（后端 v0.6.2）· 2026-10-24
>
> 所有配置都写在 **`ver2/backend/.env`** 里。第一次使用时，先复制模板：
>
> ```bash
> cd /解压路径/ver2/backend
> cp .env.example .env
> ```
>
> 改完 `.env` 后，**需要重启 `run.py` 才会生效**（在运行它的终端按 `Ctrl+C`，再重新启动）。`.env` 已加入 `.gitignore`，Key 不会被提交。

## 总览

| # | 要接什么 | 解决什么问题 | 不接会怎样 | 优先级 |
| --- | --- | --- | --- | --- |
| 1 | 高德 **Web 服务** Key | 室外步行路线规划 | 室外只能用离线缓存路线 | 高 |
| 2 | 高德 **JS API** Key + 安全密钥 | 手机页面上显示真实地图 | 地图退回成示意折线 | 中 |
| 3 | DeepSeek API Key | 听懂随意的说法、「前面有什么」看图描述 | 只能识别固定口令 | 中 |
| 4 | 障碍物检测模型 `yolov8n.onnx` | 用相机真实识别障碍物 | 只能用「模拟障碍」按钮 | 中（上真机前必须） |
| 5 | T1 机器狗桥接 | 真机执行动作、语音、行走 | 只有模拟机器狗 | 高（现场） |
| 6 | T1 相机 RTSP 视频流 | 把机器狗头部相机画面送进障碍检测 | 障碍检测没有画面 | 现场 |

第 1–4 项现在就可以在电脑上完成；第 5、6 项需要拿到机器狗以后在现场做。

## 1. 高德 Web 服务 Key（室外路线规划）

### 申请

1. 打开 [高德开放平台控制台](https://console.amap.com/)，注册并完成**个人开发者认证**。
2. 「应用管理 → 我的应用 → 创建新应用」，名称随意，比如 `moonstone`。
3. 在应用下点「添加 Key」，**服务平台选「Web 服务」**。
4. 复制生成的 Key。
5. 在控制台的流量或配额页面，确认「步行路径规划」和「关键字搜索 / 地理编码」每天能调用多少次。个人认证后的免费额度以控制台显示为准，本项目演示用量很小。

### 填写

```ini
AMAP_KEY=你的Web服务Key
OUTDOOR_CITY=上海
# 演示起点，GCJ-02 坐标，格式为「经度,纬度」
OUTDOOR_DEFAULT_ORIGIN=121.xxxxxx,31.xxxxxx
```

**起点坐标怎么取：** 用 [高德坐标拾取器](https://lbs.amap.com/tools/picker) 搜索演示地点（比如张江人工智能小镇的某个入口），点一下地图就能复制坐标。拾取器给出的就是 GCJ-02 坐标，可以直接填。

手机页面上的室外演示默认用这个预设起点，因为用 http 打开时浏览器不允许读取定位。

### 验证

重启后，在调试页切换到「室外」，输入一个目的地（比如「张江科学会堂」），点「规划」：

- 返回步骤列表，并且**没有**「离线缓存路线」标签，说明接入成功。
- 返回「未配置高德 Key」，说明 `.env` 没生效：检查文件名是不是 `.env`，再重启。
- 返回「UPSTREAM_ERROR」加高德的报错信息，说明 Key 类型不对（要「Web 服务」类型）或配额不足。

### 生成离线缓存（强烈建议）

现场网络可能不稳定。接通 Key 之后，提前把演示要用的路线存成离线缓存，这样断网时也能展示：

```bash
cd /解压路径/ver2/backend
../.venv/bin/python scripts/cache_route.py \
  --origin 121.xxxxxx,31.xxxxxx \
  --destination 张江科学会堂 \
  --name 张江科学会堂 --alias 科学会堂
```

生成的文件在 `backend/data/demo_routes/`。之后可以删掉自带的占位文件 `sample.json`，它不是真实路线。

## 2. 高德 JS API Key + 安全密钥（手机页面显示地图）

### 申请

1. 在同一个应用下再「添加 Key」，**服务平台选「Web 端（JS API）」**。
2. 创建后，控制台会同时显示 **Key** 和 **安全密钥**，两个都要复制。

> 注意：JS API 的 Key 和第 1 步的 Web 服务 Key 是**两种不同类型**，不能混用。

### 填写

```ini
AMAP_JS_KEY=你的JSAPI的Key
AMAP_SECURITY_CODE=对应的安全密钥
```

安全密钥会发给局域网里打开页面的设备。这是演示用的简化做法，**不要把这个后端部署到公网**。

### 验证

重启后，在调试页的室外模式下规划一条路线，「地图」区域应该显示真实的高德地图和路线，而不是灰色示意图。

## 3. DeepSeek API Key（语音助手、看图）

### 申请

1. 打开 [DeepSeek 开放平台](https://platform.deepseek.com/)，注册、登录。
2. 「API Keys → 创建 API Key」，复制。Key 只显示一次。
3. 账户需要有余额，按调用量计费。

### 填写

```ini
DEEPSEEK_API_KEY=sk-xxxxxxxx
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
LLM_ENABLED=true
```

`deepseek-flash` 这个模型名来自第三方资料，**以 DeepSeek 官方文档为准**。

### 验证（必须先做）

```bash
cd /解压路径/ver2/backend
../.venv/bin/python scripts/check_llm.py
```

脚本会发一次纯文本请求和一次带图片的请求，并打印模型名、耗时、返回内容：

- **两次都成功**：语音助手和「前面有什么」看图功能都可用。
- **文本成功、图片失败**：模型名可能不支持看图。去官方文档查支持图片输入的模型名，改 `DEEPSEEK_MODEL` 后再试。看图失败不影响语音控制，「前面有什么」会改用检测结果拼成一句话回答。
- **都失败**：检查 Key、余额和网络。如果开着代理，确认它没有拦截 `api.deepseek.com`。

### 接入后的变化

在调试页的口令框里试试：「先打个招呼，然后带我去门口」。日志面板里 `via` 显示 `llm`，就说明走的是大模型。没接或者超时（超过 5 秒）时，会自动退回关键词识别，显示 `via: keywords`，演示不会中断。

## 4. 障碍物检测模型（不是 API，但必须手动准备）

本仓库不附带模型。需要在一台**能正常安装 Python 包的电脑**上导出：

```bash
pip install ultralytics
yolo export model=yolov8n.pt format=onnx
```

把生成的 `yolov8n.onnx` 复制到：

```
/解压路径/ver2/backend/models/yolov8n.onnx
```

重启后，启动日志里不再出现「检测模型文件不存在」。

**说明：**

- 这个模型能识别人、椅子、长凳、行李箱、背包、自行车、盆栽等 80 类常见物体，**不能识别纸箱**。演示用的障碍物尽量选人、椅子。
- Ultralytics 使用 AGPL 许可证。比赛开源提交没有问题，**商用前**需要换模型或购买授权。
- `.onnx` 文件已加入 `.gitignore`，不会被提交。

**没有机器狗时怎么测：** 用手机录一段在演示区走动的视频，然后：

```ini
OBSTACLE_SOURCE=video
VIDEO_PATH=/完整路径/demo.mp4
```

重启后，调试页的相机区域会循环播放这段视频，并画出检测框和通行区域，可以用来调阈值（`STOP_HEIGHT_RATIO`、`CAUTION_HEIGHT_RATIO`、`ZONE_*`）。

## 5. T1 机器狗桥接（现场）

**原理：** 机器狗上跑一个桥接程序 `ver2/bridge/bridge.py`，它主动连接你电脑上的后端。T1 的 SDK 只能在机器狗自己的 Ubuntu 22.04 + ROS2 环境里运行。

### 5.1 网络

手机开热点，电脑和机器狗都连这个热点。

- 电脑的地址：在电脑上运行 `run.py`，终端会打印出来，例如 `172.20.10.14`。
- 机器狗的地址：在机器狗终端运行 `hostname -I` 查看。

T1 怎么连 Wi-Fi，请设备负责人协助。

### 5.2 电脑端（后端）

在 `.env` 里填：

```ini
ROBOT_BACKEND=bridge
# 自己定一个口令，机器狗那边要填同一个
BRIDGE_TOKEN=换成一个口令
```

然后重启 `run.py`。此时调试页显示「机器狗离线」，这是正常的，因为桥接还没连上。

### 5.3 先在电脑上验证链路（推荐）

不用真机，用模拟适配器把整条链路跑一遍。另开一个终端：

```bash
cd /解压路径/ver2
.venv/bin/python bridge/bridge.py \
  --backend ws://127.0.0.1:8000/ws/bridge \
  --token 你的口令 --adapter mock
```

调试页变成「机器狗在线（bridge）」，就说明链路正常。

### 5.4 机器狗端

把 `ver2/bridge/` 目录复制到机器狗上，再按 **`ver2/bridge/README.md`** 操作。要点如下：

```bash
# 1. 加载 ROS2 和 aimdk_msgs 环境（具体路径问设备负责人）
source /opt/ros/humble/setup.bash
source <aimdk_msgs 的 install>/setup.bash

# 2. 获取官方 SDK（桥接要用其中的状态机模块）
git clone https://github.com/PrimebotTech/primebot-t1-sdk.git
pip3 install websockets

# 3. 启动桥接（IP 填电脑在热点里的地址）
python3 bridge/bridge.py \
  --backend ws://172.20.10.14:8000/ws/bridge \
  --token 你的口令 \
  --adapter t1 \
  --sdk-path ~/primebot-t1-sdk
```

### 5.5 真机验证顺序（不要跳步）

验证前先清场，并且**一定要有人手持遥控器**。

1. 只读：调试页显示电量、动作状态。
2. 播报和灯光：点「打个招呼」之前，先在口令框发一句话，确认机器狗出声。
3. 站起、坐下、趴下。
4. 打招呼、聆听。如果命令**被接受但机器狗不动**，重启桥接时加上 `--mimic-operation 2` 再试。
5. 低速前进 1 米、左转 90°：
   - **确认方向**：如果左转变成了右转，告诉开发者调整符号。
   - **标定**：用卷尺量实际走了多少米，把实际距离除以 1，填进 `.env` 的 `CALIB_LINEAR_SCALE`。转向同理，标定 `CALIB_ANGULAR_SCALE`。
6. 断线测试：机器狗走动时关掉电脑上的后端，机器狗应在约 1–3 秒内停下。
7. 室内整条路线连续跑 3 次。

### 5.6 室内地图

`backend/data/indoor_map.json` 里的航点坐标是**示例**。到现场后要量好演示区，把「起点、服务台、咖啡桌、门口」改成实际坐标（单位：米）。

## 6. T1 相机视频流（现场，接在第 4、5 项之后）

```ini
OBSTACLE_SOURCE=rtsp
RTSP_URL=rtsp://机器狗IP:2554/live_head_stereo_left
# 画面上下颠倒就改成 180
FRAME_ROTATE=0
```

重启后，调试页的相机区域应显示机器狗的实时画面。

- **打不开**：确认电脑能访问机器狗的 2554 端口，再检查 IP。
- **画面倒置**：调整 `FRAME_ROTATE`。
- **相机看不到脚下**：四足形态下相机的高度和视角需要现场确认。

接通后要实测「障碍出现 → 机器狗停下」一共用了多久。超过 1 秒的话，把 `LINEAR_SPEED` 降到 0.2–0.25，并把通行区域拉长（调小 `ZONE_TOP_Y`），让机器狗更早停下。

## 7. 可选配置

| 配置项 | 什么时候改 |
| --- | --- |
| `LAN_HOST=172.20.10.14` | 启动时二维码地址不对，手机打不开（报 `NSURLErrorDomain`） |
| `PORT=8001` | 8000 端口被占用 |
| `OBSTACLE_AUTO_RESUME=true` | 希望障碍清除后机器狗自动继续走，而不是等用户说「继续」 |
| `MOCK_TIME_SCALE=0.3` | 用模拟机器狗演示时，想让动作快一点 |

## 8. 改完配置后的检查

```bash
cd /解压路径/ver2/backend
../.venv/bin/python run.py
```

打开 `http://localhost:8000/api/health` 和 `http://localhost:8000/api/config/public`，就能看到当前的机器人模式、是否接入了大模型、障碍物数据来源等信息。

遇到问题，把终端输出或页面报错发给开发者。
