## 1. 从 T1 文档中确认的事实

这些事实直接决定了接口怎么设计。本次读过 `接口说明.md` 和 `examples/python/` 下的运动、语音、电量相关示例。

### 1.1 四足可以走，但要按状态机切换

- 状态机（接口说明 §2.1.1.1）：
  - 上电后的起点是 `PASSIVE_DEFAULT`（零力矩）。
  - 起身路径是 `PASSIVE → QUADRUPED_STAND_DEFAULT`（四足站立），再到 `QUADRUPED_LOCOMOTION_DEFAULT`（四足行走）。
  - 站立状态和趴下（`QUADRUPED_GET_DOWN_DEFAULT`）、坐下（`QUADRUPED_SIT_DOWN_DEFAULT`）之间可以互相切换。
  - **不支持越级切换**，非法跳转会被底层拦截。
- 切换接口用 `/aimdk_5Fmsgs/srv/SetMcAction`。
  - 下发后要轮询 `/aimdk_5Fmsgs/srv/GetMcAction`，直到 `status` 从 `200 TRANSITION` 变成 `100 RUNNING`，才能下发下一条指令。
  - 两次请求至少间隔 500 ms，否则返回 `-10001`。
- 官方示例 `common/mc_action_switcher.py` 已经实现了「自动找合法路径 + 等待 RUNNING」，**桥接直接复用它，不自己重写状态机**。

### 1.2 行走靠速度流，不是「走 1 米」这种命令

- 走跑控制是 `/aima/mc/locomotion/velocity` 话题，消息类型 `McLocomotionVelocity`。
  - 字段：`forward_velocity`、`lateral_velocity`、`angular_velocity`。
  - 发布频率要求 **50–100 Hz**。
  - 速度要么为 0，要么绝对值 ≥ 0.2（m/s 或 rad/s）。
- 发布前要先用 `SetMcInputSource` 注册输入源，结束时删除（`ADD=1001` / `DELETE=1003`）。
  - 输入源名称不能和系统内置的 `rc`、`pnc`、`interaction`、`vr`、`app_proxy`、`coreon_fusion` 重名。
- **自带看门狗**：某个输入源超过 1000 ms 没有新指令，系统会自动释放控制权或安全停机。所以桥接进程一旦崩溃，机器狗会停下。
- 优先级：
  - 文档建议 SDK 二次开发用 **20–39**，遥控器 `rc` 是 80。
  - 示例代码写的是 80，但我们取 **30**，保证实体遥控器永远能抢回控制权。
- 文字说明里写的前置模式是双足，示例代码切换的却是 `QUADRUPED_LOCOMOTION_DEFAULT`。以示例为准，**待验证**。
- **所以「前进 1 米」只能换算成「0.3 m/s 持续约 3.3 秒」。** 文档里没有里程计、定位、雷达接口（全文检索过），室内位置只能按执行过的命令推算。

### 1.3 准备动作有现成资源

- 四足 Mimic 动作通过 `/aimdk_5Fmsgs/srv/SetMcMotion` 执行，传 `motion` 名称即可。
  - 可选动作：`QUAD_MIMIC_GREET`（打招呼）、`QUAD_MIMIC_HEED`（聆听）、`QUAD_MIMIC_GLANCE`（四处看、亮相）、`QUAD_MIMIC_HANDSHAKE`（握手）、`QUAD_MIMIC_PONDER`（思考）等。
  - 执行时系统会从 `QUADRUPED_LOCOMOTION_DEFAULT` 自动进入动作，做完自动回到原状态。
  - 接口是异步的：返回 `task_id` 只表示动作已入队。
- 预设动作服务 `SetMcPresetMotion` 的示例会先切到双足（`BIPED_LOCOMOTION_WBC`）。**四足形态不用它**，否则会触发变形。
- 灯带用 `/aimdk_5Fmsgs/srv/LedStripCommand`，有绿色流水、彩虹、律动、红色快闪等模式。

### 1.4 语音、电量、相机

| 能力 | 接口 | 要点 |
| --- | --- | --- |
| 播报 | `/aimdk_5Fmsgs/srv/PlayTts` | 建议 100 字以内。`is_interrupted` 控制是否打断当前播报。返回成功只代表已入队，`estimated_duration` 固定为 0，文档建议按约 200 ms/字估算播报时长 |
| 语音识别 | `/aima/agent/asr_result` 话题 | 只处理 `is_final=true` 的结果，按 `event_id` 去重 |
| 电量 | `/aima/hal/bms/state`，1 Hz | 读 `remaining_capacity_percentage` |
| 相机 | `/aima/hal/camera/CaptureJpegImage` | Beta 接口，约 1 fps，串行调用；四足形态下的画面朝向**待验证** |

### 1.5 急停的正确理解

- `DAMPING_DEFAULT` 和 `PASSIVE_DEFAULT` 是「急停」状态，但进入后机体会卸力，**行走中触发可能导致机器狗瘫倒**。
- 因此 App 上的「停止」= 速度立刻置零并停止下发，机器狗保持站立。
- 真正的急停靠**实体遥控器**（优先级 80）。阻尼/零力矩**不开放给 App**。

- 桥接主动连接后端（`ws://<后端IP>:8000/ws/bridge`），后端不需要知道机器人内网 IP。

## 3. 两种演示模式

后端维护一个全局的 `demo_mode`，前端切换。**模式决定哪些命令被允许执行**，这是安全兜底，不只是界面上的区别。

| | 室外模式 `outdoor` | 室内模式 `indoor` |
| --- | --- | --- |
| 地图 | 高德地图，真实园区步行路线 | 自建演示区平面图（米制坐标，航点 + 连线） |
| 起终点 | 手机定位或预设起点 → 输入目的地 | 选择航点，如「起点」「咖啡桌」「门口」 |
| 机器狗 | **禁止移动**。只执行准备动作序列：起身 → 打招呼 → 播报路线概况 → 聆听 → 灯光 | 站起后按航点执行「转向 + 直行」，前端图标同步移动 |
| 语音 | 「去 X 怎么走」→ 规划 + 播报 | 「带我去门口」→ 规划 + 真实行走 |
| 被拒绝的命令 | `move` / `turn` / `nav_execute`，返回 `MODE_FORBIDDEN` | 无 |

### 室外准备动作序列（示例）

```text
stand_up（PASSIVE → QUADRUPED_STAND_DEFAULT → QUADRUPED_LOCOMOTION_DEFAULT）
→ led(GREEN_FLOW)
→ mimic(QUAD_MIMIC_GREET)
→ speak("路线已规划，全程约 420 米，步行约 6 分钟，第一步向东直行 80 米")
→ mimic(QUAD_MIMIC_HEED)
```

整个序列由后端编排，每一步的结果都推送给前端。路线步骤可以继续用语音逐条播报（「下一步」），机器狗原地不动。

### 室内行走规则

- 演示区现场实测，例如 6 m × 4 m，航点写在 `data/indoor_map.json`；最短路径用 Dijkstra。
- 每段路径拆成两条命令：
  - `turn`：角速度 0.5 rad/s，时间 = 角度 ÷ 角速度；
  - `move`：线速度 0.3 m/s，时间 = 距离 ÷ 速度。
- 两段之间停 0.5 s，等机身稳定。
- 上限：单段 ≤ 3 m，单次转向 ≤ 180°，线速度在 0.2–0.4 m/s 之间。
- 实际速度与指令速度的比例需要现场标定，结果写回配置（`calib.linear_scale`、`calib.angular_scale`）。
- 前端显示的是「估计位置」，并会注明这一点。

## 4. 硬件接口设计（本阶段写好，真机到位后接入）

### 4.1 `RobotGateway` 抽象接口（后端侧）

```python
class RobotGateway(Protocol):
    async def connect(self) -> None
    async def get_state(self) -> RobotState            # 在线、电量、当前 action、忙闲
    async def stand_up(self) -> CmdResult              # → QUADRUPED_LOCOMOTION_DEFAULT
    async def posture(self, name: Literal["stand", "sit", "lie_down"]) -> CmdResult
    async def mimic(self, motion: MimicName) -> CmdResult        # 白名单：GREET/HEED/GLANCE/HANDSHAKE/PONDER
    async def move(self, distance_m: float) -> CmdResult         # 内部换算为速度 × 时间
    async def turn(self, angle_deg: float) -> CmdResult          # 正数左转，负数右转
    async def stop(self) -> CmdResult                            # 速度置零，保持站立
    async def speak(self, text: str, interrupt: bool = False) -> CmdResult
    async def led(self, mode: LedMode) -> CmdResult
    async def snapshot(self) -> bytes | None                     # P1
    def on_event(self, handler: Callable[[RobotEvent], None])    # 状态 / ASR / 错误事件
```

- **MockRobot**：
  - 用 `asyncio.sleep` 模拟耗时：起身 3 s，Mimic 4 s，行走按距离计算。
  - 状态变化和真机一致，电量缓慢下降。
  - 可以注入故障，例如 `MOCK_FAIL=move` 时让 `move` 返回失败，用来测试前端的错误显示。
- **BridgeRobot**：把调用转换成 4.2 节的 JSON 命令发给桥接，等待结果或超时。

### 4.2 后端 ↔ 桥接协议

```jsonc
// 后端 → 桥接
{"type":"cmd","id":"c-12","name":"move","args":{"distance_m":1.0},"deadline_ms":12000}
{"type":"cmd","id":"c-13","name":"stop","args":{}}
{"type":"ping","ts":1729740000}

// 桥接 → 后端
{"type":"hello","robot":"T1","sdk_commit":"a46030001300","adapter_ver":"0.1"}
{"type":"ack","id":"c-12"}
{"type":"result","id":"c-12","ok":true,"detail":{"duration_s":3.4}}
{"type":"result","id":"c-14","ok":false,"error":"ACTION_SWITCH_FAILED","message":"-1001 ..."}
{"type":"state","battery":76,"action":"QUADRUPED_LOCOMOTION_DEFAULT","status":"RUNNING","busy":false}
{"type":"asr","event_id":"e-88","text":"带我去门口","is_final":true,"confidence":0.91}
{"type":"pong","ts":1729740000}
```

**`stop` 不排队**：桥接收到后立即把速度置零，并中断正在执行的命令。

### 4.3 T1Adapter（桥接侧）实现映射

| 命令 | T1 实现 | 依据 |
| --- | --- | --- |
| `stand_up` | `McActionSwitcher.switch_to("QUADRUPED_LOCOMOTION_DEFAULT")` | `set_mc_action.py`、状态机图 |
| `posture` | 先切回 `QUADRUPED_STAND_DEFAULT`，再切到 `..._SIT_DOWN_DEFAULT` 或 `..._GET_DOWN_DEFAULT` | 状态机图 |
| `mimic` | 先确认处于 `QUADRUPED_LOCOMOTION_DEFAULT`，再调用 `SetMcMotion(motion=QUAD_MIMIC_*)`；用 `GetMcAction` 轮询，等它回到行走状态 | 接口说明 SetMcMotion |
| `move` / `turn` | 启动时注册输入源（名称 `moonstone_nav`，优先级 30，超时 1000 ms）；用 50 Hz 定时器发布速度，持续 T 秒后置零；退出时删除输入源 | `mc_locomotion_velocity.py` |
| `stop` | 速度置零并立即发布；取消定时任务 | 同上 |
| `speak` | `PlayTts`：`priority_level` 用 `INTERACTION_L6`，`trace_id` 用命令 id；完成时间按 200 ms/字估算后再返回 `result` | 接口说明 PlayTts |
| `led` | `LedStripCommand.led_strip_mode` | 接口说明 灯带 |
| 状态 | 订阅 `/aima/hal/bms/state`，并定期调用 `GetMcAction`，合并后 1 Hz 上报 | 接口说明 BMS / GetMcAction |
| ASR | 订阅 `/aima/agent/asr_result`，只转发 `is_final` 结果，按 `event_id` 去重 | `get_asr_result.py` |

桥接的看门狗分三层：

1. 3 秒收不到后端的 `ping`，桥接自己执行 `stop`；
2. 桥接进程退出后，速度流中断，系统 1000 ms 后自动脱锁；
3. 现场人员手持遥控器，随时可以接管。

**本阶段桥接只写代码骨架和 Mock 自测，不上真机。** 上真机时按第 7 节的顺序逐项验证。

## 5. 给前端的接口（本阶段定稿 v0.1，前端接入时再调整）

## 6. 语音助手

```text
输入：机器人 ASR 最终结果 / 手机录音（P1）/ 文字
 → 快速通道（不经过 LLM）：
     「停」「别动」「停下」→ stop，结束当前动作
     「停一下」「等一下」→ nav_pause，保留路线进度
     「继续」「走吧」→ nav_resume，从剩余路程继续
 → LLM 函数调用（工具 = 命令白名单 + 导航工具 + 状态查询）
 → 按当前演示模式校验（室外拒绝移动类命令，并用语音说明原因）
 → 参数裁剪（距离、角度上限）→ 任务调度执行 → speak 回复 + 推送前端
```

- **工具列表**：
  - 机器狗：`robot_stand_up`、`robot_posture`、`robot_mimic`、`robot_move`、`robot_turn`、`robot_stop`、`robot_speak`；
  - 导航：`nav_plan`、`nav_next`、`nav_repeat`、`nav_execute`、`nav_pause`、`nav_resume`、`nav_cancel`；
  - 查询：`get_status`。
- **上下文**：后端自己保存最近 5 轮对话、当前模式和当前路线，每次请求都显式带上。
- **降级**：LLM 超时（5 s）或不可用时，改用关键词规则（站起、坐下、打招呼、前进、左转、右转、停、下一步），保证演示不中断。
- **LLM 服务**：DeepSeek V4.1 Flash，走 OpenAI 兼容接口和函数调用（tools）。代码只依赖一个 `LLMClient` 接口，模型名放在 `.env` 里。据第三方资料，官方 API 的模型名是 `deepseek-flash`，并支持图片输入（见第 13.4 节）。以 DeepSeek 官方文档为准，接入时先用一次真实请求确认。
- **LLM 的定位是增强，不是依赖**：关键词规则就能覆盖全部固定命令；LLM 负责处理自由说法、组合指令（如「先打个招呼再带我去门口」）、提取目的地，以及生成自然的回复。
- **PrimeBuddy**：不同时运行，避免和我们的后端抢同一句话。原厂语音 Agent 是否需要关闭由设备负责人确认；若关闭后 ASR 话题不再输出，就以手机录音或文字作为语音入口。**待验证。**

## 9. 风险

| 风险 | 对策 |
| --- | --- |

| 没有里程计，室内位置有误差 | 显示为「估计位置」；地面贴航点标记；每次演示从固定起点出发 |

## 10. 已确认的决定

1. **室外模式禁止移动类命令**：由后端拒绝，不只是前端隐藏按钮。
2. **室外准备动作序列**：起身 → 打招呼 → 播报路线 → 聆听，同时亮绿色灯带。握手、四处看（GLANCE）作为备选动作。
3. **App 的停止只做速度置零**：真正的急停交给实体遥控器。
4. **速度流优先级取 30**：落在文档推荐的 SDK 区间，低于遥控器的 80。
5. **自带 `/debug` 调试页**：前端完成前用于测试和演示，前端接入后停用。
6. **地图**：高德开放平台个人开发者 Key（非商用）。要在控制台确认步行路径规划 v5 和 JS API 的每日配额；备选方案见第 11 节。
7. **LLM**：DeepSeek V4.1 Flash，作为可选增强；关键词规则保底，模型名以官方文档为准。

## 11. 地图服务备选

| 方案 | 优点 | 缺点 |
| --- | --- | --- |

## 12. 现场网络与手机访问

### 12.1 方案：手机开热点，电脑和机器狗都连这个热点

```text
            手机（开热点，同时打开网页 App）
           ╱                              ╲
   电脑（后端，0.0.0.0:8000）        T1 大脑板（桥接）
           ╲______ 同一个热点网段 ______╱
```

- 手机浏览器访问 `http://<电脑在热点里的 IP>:8000`。前端完成前访问 `/debug`，完成后访问前端页面。
- 桥接配置 `BACKEND_URL=ws://<电脑 IP>:8000/ws/bridge`，主动连后端。
- 热点同时提供 4G/5G 外网，DeepSeek 和高德都能正常访问。
- 比场馆 Wi-Fi 更稳妥：公共 Wi-Fi 常常开启「客户端隔离」，设备之间互相访问不了。

### 12.2 要提前确认或处理的事

| 事项 | 做法 |
| --- | --- |
| **T1 连接热点**（待现场操作） | 接口说明的 RTSP 章节写明，机器人可以连接 Wi-Fi 或热点，连接后用 `hostname -I` 查看 IP。具体怎么设置 Wi-Fi，要问设备负责人。`10.1.1.100/101` 是机器人内部有线网络的地址 |
| T1 连不了热点时 | 方案 B：电脑用网线或机器人自带的 Wi-Fi 连 T1，同时用另一张网卡（或 USB 网卡）连手机热点，电脑同时接两个网络。方案 C：后端直接部署在 T1 大脑板上，手机连机器人自带的 Wi-Fi 访问（外网需另外解决） |
| 后端要对局域网开放 | 用 `uvicorn --host 0.0.0.0` 启动；macOS 防火墙放行 Python 或 8000 端口 |
| IP 会变 | 后端启动时在终端打印访问地址和二维码，手机扫码打开；也可以试 `http://<电脑名>.local:8000`（iOS 一般支持） |
| 手机能否访问热点里的设备 | 安卓热点一般可以；iPhone 热点要现场实测一次。不行的话换另一台手机开热点，或带一个随身路由器备用 |
| 热点断开 | 手机接充电；iPhone 的热点页面保持打开，避免没有设备连接时自动关闭；关闭省电模式 |

### 12.3 HTTP 内网访问的限制

浏览器规定，**定位和麦克风只能在 HTTPS 或 localhost 下使用**，用 `http://192.168.x.x` 打开时这两个功能会被禁用。

- **定位**：室外演示默认用预设起点（第 9 节已有此方案），不依赖手机定位。
- **麦克风**：语音优先走 T1 自带的麦克风（ASR 话题）；手机端保留文字输入。
- 如果一定要用手机定位或录音：后端用自签证书启用 HTTPS（`uvicorn --ssl-keyfile/--ssl-certfile`），手机第一次打开时手动信任证书。这是 P1，放在核心功能跑通之后，需要在手机上实测。
- 高德 JS API 2.0 需要 Key 加安全密钥。安全密钥由后端代理或写在配置里，不提交到代码仓库。

### 12.4 演示前检查（约 2 分钟）

1. 手机开热点，电脑和 T1 都连上。
2. 启动后端，扫码打开页面，`/api/health` 显示「后端在线」。
3. 启动桥接，页面显示机器人在线、电量正常。
4. 发一条文字口令「打个招呼」，T1 执行；再测一次停止。

## 13. 障碍物识别（室内领行时使用）

### 13.1 T1 文档里有什么、没有什么

- **有**：头部双目相机的 RTSP 视频流 `rtsp://<机器人IP>:2554/live_head_stereo_left`（`right` 同理）。同一局域网内的电脑可以直接拉流，需要放行 2554 端口。
- **有**：通用失败原因里有 `REASON_OBSTACLE_FORWARD/BACK/LEFT/RIGHT/UP`（前、后、左、右、上方有障碍物），TTS 优先级里也有「避障受阻」这类预警。说明机器人内部可能有障碍判断。但文档**没有提供障碍物数据的话题**，速度流也没有回执，所以**不能依赖它**。只要服务返回了这些原因码，就照实推给前端和语音。
- **没有**：雷达、点云、深度图、里程计接口（已全文检索）。双目硬件虽在，但没有现成的深度输出，自己做双目测距需要标定，比赛期间不做。

**结论**：障碍物识别由我们自己用相机加视觉模型实现，判断「画面中前方有没有物体挡路」，**不输出精确距离**。它是辅助安全措施，演示时仍然需要人陪同、手持遥控器。

### 13.2 方案：电脑拉流 + 轻量检测模型 + 通行区域判断

```text
T1 头部相机 ──RTSP──▶ 后端 ObstacleMonitor（电脑上的独立线程）
                       │ 只取最新一帧，约 10 fps
                       ▼
                 目标检测（轻量 YOLO 类模型，ONNX 格式，在 CPU 上运行）
                       ▼
            通行区域判断（画面下方中间的梯形区域）
                       ▼
     clear / caution / stop ──▶ 任务调度：stop 时暂停导航，并播报「前方有障碍，我先停一下」
                       └──────▶ 推送 obstacle.update；/api/vision/stream 显示带框的画面
```

- **判断规则**（阈值现场标定）：
  - 检测框的底边进入通行区域，且框高占画面比例超过阈值 A → `stop`；
  - 比例在 B 到 A 之间 → `caution`，降到最低速度；
  - 其余情况 → `clear`。
- **防抖**：连续 2 帧判定为 `stop` 才触发。清除后要连续 1.5 秒都是 `clear`，才允许继续。
- **障碍清除后怎么办**：默认先播报「前方已通畅，说"继续"出发」，等用户确认后再走，不自动恢复。是否改成自动继续，由现场决定。
- **只停不绕**：没有定位，无法规划绕行路线。遇到障碍只做「停下、提醒、等清除或等人工处理」。
- **只在室内导航执行时生效**。室外模式机器狗不移动，检测画面只用来展示。
- **相机和视角**：先用 `head_stereo_left`。四足形态下画面朝向是否需要旋转、视野是否覆盖前方地面，都**待验证**。如果相机太高、看不到脚下近处，就在演示区摆放较高的障碍物，比如人或纸箱，并在路演中说明这一局限。
- **检测模型**：用通用物体类别（人、椅子、箱子、包等），导出为 ONNX 格式，用 `onnxruntime` 运行，Mac 上不依赖 GPU。如果使用 Ultralytics YOLO，要注意它采用 AGPL 许可证；比赛开源提交没问题，以后商用需要换模型或购买授权。

### 13.3 延迟预算

- 机器狗以 0.3 m/s 行走时，**每 1 秒延迟就多走 30 cm**。RTSP 拉流延迟、检测耗时、命令下发都要算进去。
- 现场实测「障碍出现 → 机器狗停下」的总耗时，再据此设置触发阈值和最高速度。
- 如果总延迟超过 1 秒，就把室内速度降到 0.2–0.25 m/s，并把触发区域拉长（让机器狗更早停下）。

### 13.4 「我前面有什么」（P1）

- **主路径：用 DeepSeek V4.1 Flash 看图回答。**
  - 取一张 `CaptureJpegImage` 单帧，压缩到长边约 1024 像素，编码成 base64 data URL。
  - 按 OpenAI 格式放进 user 消息的 `content` 数组（`{"type":"image_url","image_url":{"url":"data:image/jpeg;base64,..."}}`）。
  - 同时附上检测模型给出的类别和位置，让回答有依据，比如「正前方有一把椅子，左边有人」。
  - 提示词要求：只描述画面里看得到的东西，不报具体距离，看不清时直接说看不清。
- **兜底**：大模型超时（5 秒）或不可用时，直接用检测结果拼成一句话播报。
- **依据**：多家第三方资料（OpenRouter、SiliconFlow、Apidog、CometAPI）都说 V4.1 Flash 原生支持图片输入，官方 API 的模型名是 `deepseek-flash`。DeepSeek 官方文档没有出现在搜索结果里，所以拿到 Key 后先发一次带图请求，确认模型名、图片格式和耗时。
- **只用于问答，不用于避障**：一次看图请求要几秒，赶不上实时判断；行走中停不停车只由第 13.2 节的本地检测决定。

### 13.5 接口留口与开发顺序

- `ObstacleSource` 接口有三种实现：
  - `RtspObstacleSource`：真机，拉取 RTSP 视频流；
  - `VideoFileObstacleSource`：读取本地录好的视频，方便在 Mac 上调试检测和阈值；
  - `MockObstacleSource`：由 `/api/debug/obstacle` 手动触发。
- 调度器只关心 `clear` / `caution` / `stop` 三种状态，和数据来自哪里无关。
- **开发顺序**：
  1. 阶段 A：完成暂停/继续，以及 Mock 障碍源；
  2. 用手机录一段演示区视频，跑通检测和阈值调参；
  3. 阶段 B：拉取真机 RTSP，实测延迟，跑通「行走中遇到障碍停下 → 清除后说"继续"」。
